# 다수 원도급사·현장별 양식 대응 설계안

## 1. 목적과 현재 상태

골조 협력사는 최대 15개 활성 현장에서 여러 원도급사와 일한다. 같은 원도급사라도 현장별 요구와 양식이 다를 수 있으며 협력사 자체 관리가 필요한 항목도 있다. 원도급사 양식과 협력사 자료를 분리해 보존하면서, 같은 내용을 반복 입력하는 부담을 줄이는 것이 목표다.

v0.28에서 현장별 원도급사 관계 및 일부 정정, 요구사항·양식 목록과 정정 이력, 선택적 적용 기간을 로컬 가상자료로 구현했다. 원도급사 통합 목록과 종료일 정정, 양식 원본 파일 보관·자동작성·외부 제출은 아직 구현되지 않았다. 이 문서는 개발 방향이며 법령 해석이나 원도급사 승인된 업무 절차가 아니다.

## 2. 업무 구성 원칙

- 협력사 본사와 현장이 주체이며, 원도급사는 현장에 연결되는 별도 거래처다. 한 원도급사가 여러 현장을 맡을 수 있고 한 현장에 원도급사 변경·복수 관계가 생길 가능성을 열어둔다. 무조건 한 현장당 한 회사로 고정하지 않는다.
- 실제 업무에 사용할 기준은 협력사 자체 기준, 원도급사 공통 기준, 현장별 추가·변경 지시를 출처와 적용 기간별로 기록한다. 서로 충돌하거나 불명확하면 자동으로 우선순위·적법성을 결정하지 않고 담당자 확인 대상으로 표시한다. 원도급사 요구가 협력사 또는 법령상의 의무를 자동으로 대체하지 않는다.
- 같은 원도급사의 다른 현장 설정을 자동 공유하지 않는다. 담당자가 적용 대상을 확인한 뒤에만 복사·반영하며, 현장별 예외와 변경 이력을 보존한다.
- 현장에 맞는 요구사항과 양식 사용 여부는 확인 전·적용·해당 없음·변경 검토 중 등으로 구분한다. 미확인을 완료나 비적용으로 표시하지 않는다.
- TBM 참석 대상, 본인확인·서명, 교육별 이수·누락은 프로그램 저장의 공통 필수조건이 아니다. 실제 현장에서 적용되는 의무와 관리 주체는 별도로 확인한다.

## 3. 제안하는 구성

| 구성 | 관리할 내용 | 구분할 점 |
|---|---|---|
| 원도급사 | 명칭, 식별 정보, 참고 연락처(필요할 때만) | 협력사 조직·사용자와 분리 |
| 현장-원도급 관계 | 현장, 원도급사, 관계 유형, 적용 시작·종료, 확인 상태 | 한 현장의 변경 이력을 남김; 복수 관계는 실증 후 적용 |
| 업무 요구사항 | 업무명, 출처, 적용 현장, 기한·주기, 담당·제출 대상, 요구 내용, 확인자·확인일, 예외 | 법적 의무와 원도급사 지시 및 내부 기준을 각각 출처로 표시 |
| 양식 목록 | 이름, 제공자, 용도, 문서 형식, 버전·시행일, 적용 대상, 원본 위치, 변경 이력, 사용 승인 상태 | 해당 양식이 최신·승인되었다고 자동 추정하지 않음 |
| 업무 기록 | 위험요인·조치·TBM 등 현장별 기본 데이터와 선택적 추가항목 | 원도급사별로 다르게 필요한 값과 수기 확인 항목을 구분 |
| 제출 기록 | 사용한 양식 버전, 작성 당시 값, 파일·제출 경로, 제출일, 제출자, 접수 확인, 수정 이력 | 파일 생성·제출·접수·승인은 서로 다른 상태 |

예: A원도급사 1현장의 TBM은 A사의 양식 3판과 현장 추가사항을 확인해 사용하고, B원도급사 2현장은 B사 양식을 사용한다. 공통 작업 내용은 각 현장 업무 기록에서 활용하되, 현장과 제출 범위를 벗어나 공유하지 않는다. 양식에 없는 협력사 자체 점검은 별도로 기록한다. 실제 규칙은 예시가 아니라 현장에서 확인한 내용으로 등록한다.

## 4. 실제 양식 처리 단계

1. **목록과 현장 연결**: 양식명, 제공자, 적용 현장, 버전, 원본의 안전한 위치, 확인 상태를 가상자료로 기록한다. 파일 첨부 기능 전에는 위치 메모만 제공하고 원본 보관으로 표시하지 않는다.
2. **수동 작성 지원**: 현장별로 확인된 양식과 요구사항을 보여주고, 프로그램의 관련 기록을 검토용으로 확인한다. 원도급사 전용 시스템 입력·서명·승인은 기존 절차를 따른다.
3. **선택적 자동 채움**: 실제로 받은 양식의 형식·편집 가능 여부·배포 권한을 확인한 뒤 문서별로 필드 매핑을 만든다. 공통값으로 채울 수 없는 항목은 미확인으로 남기며 작성자가 원본과 내용을 대조한다. 한글(HWP/HWPX), 엑셀, PDF 등은 형식별 편집 가능성과 도구를 별도 검증한다. 모든 형식의 자동 생성을 약속하지 않는다.
4. **제출본 보존·연동**: 원본과 제출본, 적용 양식 버전, 변경 이력, 제출·접수 상태를 보존한다. 승인된 공유 범위와 접근권한을 구현한 후에만 외부 공유나 연동을 검토한다. 수동 제출을 자동 접수로 간주하지 않는다.

양식 개정 시 이전 제출본과 당시 적용 버전을 유지한다. 변경 전·후 필드를 비교하고 영향받는 현장을 표시하되, 적용 시점과 기존 기록 수정 여부는 담당자가 판단한다. 파일과 DB를 함께 안전하게 백업·복원하기 전에는 실제 원본 보관을 완료로 표시하지 않는다.

## 5. 우선순위와 수용 조건

- [ ] **1순위 F01/F16 — 원도급사와 현장 관계**: 현장별 관계 등록·조회와 별도 종료 기록은 로컬 가상자료로 구현했다. 관계 명칭·시작일 정정은 지원하며 종료일 정정·통합 식별과 실제 업무 실증이 남았다. 실제 로그인은 별도 과제다.
- [ ] **2순위 F16 — 현장별 요구사항과 양식 목록**: 출처·현장·확인 상태와 선택 버전·원본 위치 메모를 로컬에 기록한다. 메타데이터 정정과 변경 이력 및 선택적 적용 기간은 구현했으며 파일 원본 보관과 실제 업무 실증은 남았다.
- [ ] **3순위 F04/F05/F16 — 실제 원본·제출본**: 파일 권한, 저장 용량, 버전·무결성, DB와 파일의 백업·복원, 보관 정책을 구현하고 검증한다.
- [ ] **4순위 F07/F08/F14/F16 — 반복 입력 감소**: 실제 제공된 양식 중 사용 빈도가 높은 1종부터 필드 대응과 수동 검토를 실증한다. 양식 변경·누락·추가항목과 출력 결과를 확인한다.
- [ ] **5순위 — 원도급사별 제출 연동**: 기술적 허용 여부, 승인된 공유 범위, 인증, 접수 결과 및 비용을 확인한 뒤 개별 검토한다.

단계별로 유지·보완·보류·제외를 결정한다. 회사와 원도급사 간 자동 공유, 일괄 변환이나 법령 준수 판정은 구현 범위에 포함되었다고 가정하지 않는다. 개발 과정에서 추가 유료 서비스를 만들지 않는다. 실제 공동 운영은 무료 서비스 이용조건과 사내 서버 가능성을 별도로 검토한다.

## 6. 현장 실증을 위한 확인 항목

- 원도급사별로 자주 사용하는 문서 2~3종의 이름과 원본 형식, 변경 주기 및 실제 제공 경로
- 같은 원도급사 내 현장별로 달라지는 내용과 승인·제출 경로
- 협력사 자체 작성 문서와 원도급사 작성·보관 문서의 구분
- 문서별 협력사 담당 범위, 필수와 선택 항목, 실제 서명·승인 주체
- 외부 시스템 사용 여부, 원본·제출본 보관 위치와 내부 공유 범위
- 실제 양식을 샘플로 확인할 때 개인정보·회사 기밀을 지운 뒤 제공 가능한지
