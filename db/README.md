# 중앙 저장 연결 준비

현재 schema.sql은 신규 전용 프로젝트에 적용할 검증된 초안입니다. 기존 운영 DB에는 적용하지 않았습니다. 로컬 PostgreSQL(PGlite)에서 auth.uid 및 사용자 역할을 재현해 RLS를 시험했습니다. 실제 Supabase Auth 로그인·Data API 통합 시험은 전용 프로젝트 생성 후 필요합니다.

## 구성

- companies: 회사
- company_members: 회사 소속, 본사 관리자(owner)·현장 담당자(manager)·조회 전용(viewer), 활성 여부
- sites: 회사별 현장, 활성 여부와 변경 revision
- site_members: 현장 배정, 회사·현장 복합 FK로 타 회사 배정 방지
- pilot_feedback: 현장별 실증 의견, 작성자와 작성 시각

본사 관리자만 현장을 추가·종료·재개합니다. 현장 담당자는 배정된 진행 현장에 의견을 작성합니다. 조회 전용은 조회만 가능합니다. 회원 소속·현장 배정 변경 권한은 클라이언트에 주지 않습니다. 초기 회사와 계정 배정은 승인된 운영자가 대시보드에서 진행합니다. 자동 회원가입·권한 부여·이메일 발송은 구현하지 않았습니다.

## 신규 환경 연결 순서

1. 사용자가 선택한 조직에 별도 프로젝트 생성. 비영(非零) 비용은 확인 후 진행.
2. 빈 DB 여부 확인 후 schema.sql 적용. 보안 advisor 및 실제 역할별 쿼리 검증.
3. 승인된 계정 생성과 회사·현장 배정. 실제 개인정보 없이 시험.
4. Vercel 환경변수 SUPABASE_URL, SUPABASE_PUBLISHABLE_KEY 설정. publishable 키만 허용하며 secret/service_role 키는 빌드에서 거부.
5. vercel.json의 CSP connect-src에 해당 프로젝트의 정확한 HTTPS origin 추가. 현재는 미연결이므로 self만 허용.
6. 재배포 후 로그인→소속 조회→현장 등록→의견 저장→다른 계정 접근 차단→로그아웃 검증.

## 운영 전 남은 범위

중앙 의무목록, 증빙 저장, 관리자용 초대·소속 관리 화면, 변경 감사 로그, 비밀번호 복구, 세션 정책, 개인정보 취급·보관 기간은 후속 구현입니다. 현 schema는 의무 이행 완료를 판정하지 않습니다. 초기 승인까지 화면에는 연결 준비 중 상태를 표시합니다.

## 검증

`npm test`: 타 회사 차단, 미배정 현장 차단, 자기 권한 상승 차단, 조회 전용 쓰기 차단, 탈퇴·비활성화 즉시 반영, 활성 15개 제한과 종료 현장 보존, revision 충돌, 익명 조회와 삭제 차단. 실제 병렬 네트워크 요청 시험은 전용 DB에서 추가합니다.
